# Метрики и протокол оценки

## Автоматические задачи

Для каждой задачи сохраняются точность содержания и соблюдение формата.
Например, «Можно сыграть e2e4» может содержать однозначный легальный ход,
но не выполнять требование «только UCI». Эти показатели не смешиваются.
Несколько альтернатив, отрицание выбранного хода и неразбираемый ответ
не превращаются в правильный ответ выбором удобного варианта.

Вопросы о клетках проверяются по всему ответу. Одновременные «на e4 стоит
пешка» и «клетка e4 пуста» считаются противоречием. Требуется только запрошенная
клетка, однозначный тип и цвет. Пустой ответ — ошибка.

Для списков ходов считаются TP, FP, FN, precision, recall, F1 и точное совпадение
множеств. Неразбираемый ответ при пустом эталоне не засчитывается как пустой
список; требуется явное «нет» или []. Повторы не меняют содержимое множества,
но нарушают протокол формата.

Атаки/защита означают геометрическую relation attack из python-chess.
Связанная фигура сохраняет атакуемые клетки, хотя ход на них может быть
нелегальным. Мат в один принимает все легальные матующие ходы.
Мат не более чем в два проверяется полным перебором: первый ход,
каждый ответ соперника и наличие завершающего матующего хода.
Пат и окончание партии без мата опровергают такую линию.

Отсутствие мата в два в отрицательных примерах доказано этим ограниченным
полным перебором, а не отсутствием мата в выводе Stockfish.

## М1–М3 из исходного документа

М1: два вопроса на каждый исходный пример, 178 ответов. Отдельно публикуются
пустые и занятые клетки, классы фигура/цвет и macro-F1 по 13 классам.
Это меньший пилот относительно целевых 2000 ответов.

М2: точное совпадение с основной линией PGN после преобразования в UCI.
79 записей; 10 аналитических ответвлений исключены. Неответ/нелегальный ход —
ошибка. Рейтинги и контроль времени неизвестны, историческая подлинность
всех записей не подтверждалась. Это воспроизведение записанного поведения,
а не метрика силы игры.

М3: доля рекомендаций с потерей <=50 сантипешек. Stockfish 19, один поток,
Hash=128 MiB, 1 млн узлов. Лучший найденный и рекомендованный ход считаются
из исходной позиции; второй — через searchmoves. Оценки со стороны ходящего.
Отрицательная разница при независимых ограниченных поисках сохраняется
в raw_loss_cp; потеря ограничена снизу нулём.

В обычной группе пропуск/нелегальный ответ остаётся в знаменателе, если
лучшая оценка не матовая. Если лучшая или полученная оценка матовая, запись
попадает в отдельную группу: она не переводится в сантипешки. Все исходные
оценки и варианты сохраняются в scores.jsonl. Доля легальных рекомендаций
считается по всем 89 запросам.

Версия движка, SHA256 бинарника и экспортированной NNUE фиксируются в
engine/engine.json. Поддержана одна встроенная сеть Stockfish 19.
Для других сетевых архитектур нужна отдельная проверенная интеграция.

## Экспертные М4–М7

Сначала утверждаются рубрики; затем генерируются ответы; затем проводится
независимая разметка. Имя модели/этап дообучения следует скрыть от тренеров.
Эталонный комментарий автора не заменяет утверждённых обязательных идей.

- М4: подтверждённые минимальные утверждения / все проверяемые утверждения;
  итог — среднее по ответам. Неподтверждённые утверждения не засчитываются.
  Пустой ответ и ответ без проверяемых утверждений получают 0.
- М5: сумма бинарных баллов обязательных идей / число идей; итог — среднее.
  Противоречивая или только названная без раскрытия идея получает 0.
- М6: доля ответов хотя бы с одной критической ошибкой, меньше — лучше.
  Отсутствие ответа публикуется отдельно, а не как качественное объяснение.
- М7: средний принятый балл из четырёх критериев / 4. Критерии:
  цель хода, привязка к позиции, понятность для заданного уровня,
  применимый верный вывод. Два независимых тренера; при различии итогов —
  третий. Для пустого ответа балл 0 независимо от ошибочной разметки.

Общий показатель из документа — процент объяснений, одновременно прошедших
М4=100%, М5>=80%, М6=0, М7>=3/4. Это не F1 и не функция потерь обучения.
Без всех необходимых оценок результат остаётся null.

Одна запись ratings.jsonl:

~~~json
{
  "id": "legacy:001:M4_M7",
  "response_sha256": "DIGEST_EXACT_RESPONSE_USING_gigabench.io.digest",
  "factual_reviewer": "REAL_REVIEWER",
  "claims": [{"text": "ACTUAL_CLAIM", "verdict": "unconfirmed"}],
  "idea_scores": [0, 0],
  "critical_error": false,
  "coach_ratings": [
    {"coach": "REAL_COACH_A", "criteria": [0, 0, 0, 0]},
    {"coach": "REAL_COACH_B", "criteria": [0, 0, 0, 0]}
  ],
  "adjudication": null
}
~~~

Это только пример структуры, не реальные оценки. Число idea_scores должно
совпасть с утверждёнными идеями. Допустимые verdict: confirmed, incorrect,
unconfirmed. Все ID должны присутствовать ровно один раз.

## Основная метрика и блоки (v1.1)

Если у эталона есть классы (да/нет, пусто/фигура, мат/нет мата, корзины оценки позиции), основная метрика —
сбалансированная точность: среднее точностей по классам. Постоянный одинаковый ответ даёт 50%.
Иначе основная метрика — обычная точность. Рядом всегда показываются обычная точность и доля самого
частого эталона.

Каждая задача относится ровно к одному блоку (config/default.json, blocks). Значение блока — среднее
основных метрик его задач с равными весами. Блок diagnostics (ручные крайние случаи) показывается,
но в выводах не используется. Внутри задач результаты разбиваются по числу фигур и по слоям из
params.strata; для перефразированных вопросов считается доля групп с одинаковым результатом.

## Итоги и статистика

Отчёт показывает каждый блок и задачу отдельно. Дополнительный автоматический
macro-балл — среднее точностей отдельных автоматических задач без М3 и
экспертного блока. Это диагностический индекс с заданными весами, а не
универсальная эффективность обучения. При неполном прогоне он равен null.
Сравнивать индексы разных составов наборов нельзя.

Доверительные интервалы точностей и парных различий используют 2000
bootstrap-перевыборок групп. Для исторических партий группа — глава/партия,
для синтетики — исходная позиция/случайная партия, включая её дочерние вопросы.
Маленькие фиксированные группы мотивов не дают надёжной популяционной оценки.

Недостающие ручные метрики, неисполненные задачи и ошибки исполнения
различаются в машинном отчёте. Ошибки модели/исполнения на запущенных запросах
учитываются как неверные ответы; незапущенные запросы маркируются not_run,
а не ошибочно оцениваются как результаты модели.

Потолок текущего runtime: 512 позиций контекста и 64 новых токена.
Достижения лимита и ошибки контекста видны отдельно. Специальные координаты
интерпретируются через экспериментальный candidate_rank_major_start7;
совпадение с недоступной авторской реализацией не утверждается.
