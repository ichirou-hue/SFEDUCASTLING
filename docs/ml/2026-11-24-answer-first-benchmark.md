# Краткий ответ первым: протокол бенчмарка

## Новый контракт

Для новых prepares с `config/default.json` задан
`answer_protocol: "answer_first_v1"`. Автоматические задачи получают общую
инструкцию, одинаковую для всех моделей:

> Сначала дай краткий ответ отдельной строкой. Затем, если нужно, добавь
> пояснение. Пояснение необязательно.

Требования «Ответь только», «Только UCI» и «без пояснений» согласованы с
новым контрактом; нужный тип краткого ответа сохраняется. Например:

```text
Вопрос: какая фигура на e4?

e4: белая пешка
Пояснение: ...
```

Другие варианты первой строки: `Да`, `20`, `C`, `e2e4`,
`e2e4, d2d4`, `e4: пусто`. Префикс `Ответ:`/`Answer:` необязателен.
Формат конкретного типа указан в вопросе. Пояснение можно опустить совсем.
Для ходов предпочтителен UCI; однозначный SAN может быть содержательно верным,
но не соответствовать требуемому формату.

## Заморозка и совместимость

`cases.build()` применяет протокол после сборки задач. FEN, gold, IDs,
страты, seed и состав заданий остаются прежними. У автоматических cases
появляется `answer_protocol`; queries содержат преобразованный prompt.
Manifest сохраняет config, хеши задач/запросов/исходников.
Экспертные задачи `explanation` не преобразуются.

В пользовательском config можно задать `"answer_protocol": "legacy"`.
Отсутствие ключа также сохраняет legacy-подготовку.
Скоринг выбирает контракт по самому замороженному case, а не по текущему
default config: старые cases без поля используют прежний разбор.
Изменение config/кода не позволяет незаметно продолжать старый frozen-run:
для нового контракта нужен отдельный `prepare` в новый каталог.

## Скоринг

- Берётся первая непустая строка. Она должна быть законченной и однозначной:
  несколько альтернативных ходов не считаются одним ответом.
- Ответ не ищется в необязательном пояснении вместо первой строки.
- Полные поздние явные блоки ответа проверяются на согласованность.
  Перестановка одного множества ходов не является конфликтом;
  дубликаты проверяются отдельно как нарушение формата.
- Если вывод обрезан, законченная первая строка остаётся оцениваемой.
  Первая строка без перевода строки при `truncated=True` не считается
  гарантированно законченной. Оборванный повторный вывод в последней строке
  не доказывает противоречия; полные противоречащие ответы отклоняются.
- Ошибки исполнения, неизвестный результат и ожидание движка/эксперта
  не превращаются в подтверждённые успехи или шахматные ошибки.
- `content_correct` и `protocol_compliant` оцениваются раздельно.
  Семантическое качество произвольного пояснения не измеряется этим парсером.

## Границы изменения

Это изменение подготовки и скоринга **бенчмарка**. Промпты приложения и
обучающих пайплайнов автоматически не менялись; их согласование отдельно.
Исторические ответы не переписываются при смене контракта.
Каждый модельный запуск получает отдельный frozen-каталог; временные
prepare в тестах не являются прогоном модели.

Для полной автоматической подготовки добавлен `prepare --without-explanations`:
экспертные cases исключаются до freeze, их число сохраняется в
`excluded_explanation_cases`; автоматические M1–M3 не удаляются.
