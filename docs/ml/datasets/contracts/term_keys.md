# Ключи терминов: термин = комбинация фактов

Словарь устроен как «ключ → значение»: **значение** — термин из [terms_catalog.md](terms_catalog.md),
**ключ** — логическое выражение над атомарными фактами, которые считают скрипты (python-chess, Stockfish).
Термин ставится в план, только если ключ истинен. LLM термины не придумывает.

Часть 0 — **ядро v1**: ~55 терминов, сверенных с первоисточниками (код Stockfish 15.1 и разметчика lichess).
Часть 1 — атомарные факты (из чего собираются ключи). Часть 2 — ключи по всем разделам каталога (черновик; при расхождении действует Часть 0).

## Обозначения

- **X** — сторона, сделавшая ход; **O** — соперник. **P** — позиция до хода, **P′** — после.
- **L** — главный вариант движка после сыгранного хода (`best_reply.line`), **L\*** — вариант лучшего хода из P (`best_move_before.line`).
- **mat_X(·)** — материал X минус материал O (1/3/3/5/9).
- **net(L)** — изменение mat_X от P до конца L, считая само взятие хода (уже так считаем в `concepts.py`).
- **traj(L)** — последовательность mat_X после каждого полухода L (нужна для «жертвы» по образцу lichess).
- `∧` и, `∨` или, `¬` не. Пороги вида θ = … — стартовые, подлежат калибровке на эталоне.
- Статус: **ЕСТЬ** — факт/ключ уже считается; **ДОПИСАТЬ** — считается из того, что есть, нужен код;
  **ВНЕШН** — нужен внешний источник (Stockfish 15.1 `eval`, таблицы Syzygy, дебютная книга, часы из PGN, история партии);
  **НЕТ** — ключа из фактов нет (суждение, психология, служебное слово).

# Часть 0. Ядро v1 (сверено с первоисточниками, 2026-10-29)

Источники ключей:
- **SF** — Stockfish 15.1, классическая оценка: [`evaluate.cpp`](https://github.com/official-stockfish/Stockfish/blob/sf_15.1/src/evaluate.cpp), [`pawns.cpp`](https://github.com/official-stockfish/Stockfish/blob/sf_15.1/src/pawns.cpp). Константы ниже сверены с кодом дословно. Формат S(mg, eg) — бонус в миттельшпиле / эндшпиле, внутренние единицы SF.
- **LP** — разметчик задач lichess: [`tagger/cook.py`](https://github.com/ornicar/lichess-puzzler/blob/master/tagger/cook.py), [`tagger/util.py`](https://github.com/ornicar/lichess-puzzler/blob/master/tagger/util.py). Код читан по исходнику. Лицензия AGPL — правила переписываем своими словами, код не копируем.
- **НАШ** — наше правило (`gcdata/concepts.py`), первоисточника с кодом нет.

Вспомогательные функции LP (используются в ключах):
- `is_defended(sq)`: поле защищает своя фигура, **или** защита появляется, если снять с доски атакующую дальнобойную фигуру соперника (сквозная защита).
- `is_hanging(sq)` = ¬`is_defended(sq)`.
- `bad_spot(sq)`: фигуру бьют ∧ (`is_hanging` ∨ её бьёт фигура дешевле, не король).
- `is_trapped(sq)`: не пешка и не король, не под шахом, не связана, в `bad_spot`, и **каждый** её легальный ход ведёт в `bad_spot`, кроме взятия фигуры не дешевле себя.
- `mat_X` — материал 1/3/3/5/9, король не считается.

Проверка: тактика и маты — по базе задач lichess (CC0, темы проставлены разметчиком LP): точность и полнота по каждому термину.
Позиционные — по распределению составляющих SF на наших партиях + выборочная проверка.

## 0.5 Пешечная структура (дословно по SF `pawns.cpp`)

Обозначения SF для пешки на s: `neighbours` — свои пешки на соседних вертикалях; `stoppers` — пешки O впереди на своей и соседних вертикалях; `lever` — пешки O, которые бьёт пешка; `leverPush` — пешки O, которые будут под боем после шага вперёд; `blocked` — пешка O прямо перед пешкой; `phalanx` — свои соседи на той же горизонтали; `support` — свои соседи на горизонталь ниже.

## Принципы, по которым ставим ключи

1. **Тактика — по варианту, а не по одному полуходу.** Ключ проверяет, что приём реально срабатывает в L: цель теряется, материал выигран, мат поставлен (как разметчик задач lichess).
2. **Позиционные термины — по изменению**, а не по состоянию: термин про ход, а не про позицию вообще («ход создал сдвоенные пешки», а не «есть сдвоенные пешки»).
3. **Порог θ у каждого числа** и калибровка: тактика — на базе задач lichess (CC0) по точности/полноте; позиционные — по распределению на наших партиях и выборочной проверке.
4. **Нет надёжного ключа — нет термина.** Факты всё равно идут в план, но без [скобок]; LLM не имеет права назвать их термином.
5. **Ключ = определение для судьи.** Текст ключа переносится в `TERM_DEFS` судьи, чтобы судья проверял тот же смысл, что считает скрипт.
