# Руководство пользователя SFEDUCASTLING

Проект - шахматный помощник: тактические паззлы, учебный курс по правилам и дебютам,
анализ партий, тренерские объяснения ходов (ассистент в реальном времени),
персональный тест уровня и адаптивное обучение.

## Роли и права доступа

| Роль | Гостевая активность | Доступ |
|------|---------------------|--------|
| Гость (без аккаунта) | Паззлы, анализ, чат с ассистентом | Без входа в аккаунт |
| `learner` | Всё, что у гостя + учебные модули, level-test, профиль, прогресс | Регистрация (кнопка в шапке или плашка на страницах «Обучение» / «Паззлы») |
| `admin` | Всё + админ-панель `/admin` (пользователи, профили, статистика) | Назначается скриптом (см. ниже) |

Правила:
- В БД есть только две роли: `learner` и `admin` (колонка `users.role`).
  Флаг `is_admin` выводится из роли и в БД не хранится (колонка удалена миграцией `a1b2c3d4e5f6`).
  Гость - это не роль, а неавторизованный посетитель.
- Учебные модули (`/api/training/*`) и level-test доступны **только зарегистрированным**
  (learner/admin); сервер вернёт 401 без токена. Гостю показывается плашка
  «Обучение доступно после регистрации» / «Тест доступен после регистрации».
- На странице «Паззлы» гость решает свободно; когда остаются 2 задачи, появляется
  окно регистрации (чтобы сохранить прогресс).
- Время жизни токенов настраивается в `.env`: `ACCESS_TOKEN_TTL_MIN`
  (в `.env.example` - 1440 минут, то есть 24 часа) и `REFRESH_TOKEN_TTL_DAYS`
  (в `.env.example` - 30 дней). После истечения access-токена клиент делает
  `/api/auth/refresh`; при провале - выход из аккаунта.
- Логин: 3-32 символа, только латиница, цифры и символы `_` / `-`. Кириллица не принимается.
- Пароль: 8-72 символа, нужны **латинские буквы и цифры**. Хранится только bcrypt-хеш (cost 12).
- Администратор: `python -m scripts.create_admin <login> <password>`
  или `python -m scripts.init_db --admin <login> <password>`.

## Основные разделы

- **Паззлы** (`/puzzles`) - тактические задачи с подсказками ассистента.
- **Обучение** (`/training`) - курс: модули -> уроки -> задания, прогресс и интервальные повторения.
- **Тест уровня** (`/level-test`) - персональный тест из 20 задач; по результатам подбирается уровень обучения.
- **Профиль** (`/profile`) - данные пользователя, шахматные аккаунты (Lichess / Chess.com), прогресс.
- **Админка** (`/admin`, только admin) - список пользователей, профили и статистика.

При первом входе показывается онбординг-анкета; её ответы используются для
персонального подбора задач (`skill_band` / `prior_band` / `rating_estimate`).

## Запуск

### 0. Быстрый старт

```bash
# Windows
run.bat

# Linux / macOS
bash run.sh
```

Скрипт создаст venv, установит зависимости, скопирует `.env.example` в `.env`
(по умолчанию SQLite `backend.db`), прогонит миграции и запустит сервер на http://127.0.0.1:8005.

### 1. Backend (вручную, Windows / 127.0.0.1:8005)

```bash
# окружение (пример venv)
python -m venv ml-env
ml-env\Scripts\activate

pip install -r requirements.txt

# конфигурация: .env в корне проекта (DATABASE_URL, JWT_SECRET_KEY, MAIA3_*, GIGACHESS_BASE_URL ...)
# см. backend/config/settings.py и .env.example; без .env работает SQLite

# миграции + (опционально) админ
python -m scripts.init_db
python -m scripts.init_db --admin admin Parol2026   # + создание администратора
python -m scripts.init_db --check                   # проверка версии схемы

# наполнение учебного курса (идемпотентно: повторные запуски обновляют данные)
python -m backend.services.training_seed

# запуск API (раздаёт фронт из frontend/dist)
python -m backend.app
```

Для PostgreSQL поменяйте `DATABASE_URL` в `.env` на
`postgresql+asyncpg://user:pass@127.0.0.1:5432/sfeducastling` (нужен `asyncpg` вместо `aiosqlite`).

### 2. Frontend (dev-режим; продакшен-сборка раздаётся самим backend)

```bash
cd frontend
npm install
npm run dev      # http://localhost:5173, /api проксируется на :8005
npm run build    # сборка в dist/ (обновляет то, что отдаёт backend)
```

### 3. LLM-сервис (Qwen3-8B через vLLM, порт 8000)

```bash
bash start_llm.sh
```

## Тесты

```bash
# через актуальный venv (ml-env или .venv, созданный run.bat / run.sh)
ml-env\Scripts\python.exe -m pytest tests/ -q
```

Часть тестов интеграционная и использует БД из `DATABASE_URL`
(по умолчанию - локальный SQLite).

## Ветки и стейджинг

Основная ветка - `main`. Новые фичи ведём в ветках `feature-*`, которые
вливаются в `main` после проверки. В CI зарезервирована и ветка `dev`
(см. `.github/workflows/codeql.yml`), при необходимости создаётся так же:

```bash
# фича-ветка
git checkout -b feature/debuty-tasks main

# после проверки - слияние
git checkout main
git merge feature/debuty-tasks
git push origin main
```

CI:
- GitHub Actions x CodeQL (`codeql.yml`) - анализ безопасности для Python и JS/TS
  на `push` в `main`/`dev`/`feature-*` и на `pull_request` в `main`.
