# Ревью: профиль, карточка игроков и меню «Позиция»

- **Дата:** 2026-11-21
- **Ветка:** `dev` (незакоммиченные изменения)
- **Скоуп:** `frontend/src/components/{UserProfilePage.jsx,UserProfilePage.css,MoveHistory.jsx,PositionMenu.css}`, `frontend/src/{style.css,theme.css,mobile.css}`
- **Вне скоупа:** `frontend/dist/**` (пересобранный бандл), сборка и `npm test` (проверены автором правки)

## Контекст правки

Набор UI-правок:

1. `UserProfilePage.jsx` — убрано ложное «Требуется пройти анкету» при 401, ошибка сбрасывается при смене `user`, при отсутствии токена кэшированный профиль скрывается, «Прогресс уровня» встроен в блок «Прогресс» как компактный `RatingBandProgress`.
2. `UserProfilePage.css` — усилена специфичность селекторов золотой карточки GigaCoin (в светлой теме её перекрывал базовый `.user-profile-stat`), добавлены стили встроенного уровня и «плоского» `ProgressWidget`, тёмные переопределения.
3. `MoveHistory.jsx` + `style.css` + `theme.css` — карточка игроков стала вертикальной (соперник сверху, «Вы» снизу, VS по центру), добавлен `move-history-panel--empty`, чтобы пустая панель не растягивалась на всю колонку.
4. `PositionMenu.css` + `mobile.css` — кнопка «Позиция» уменьшена (30px/14px, на мобильном 28px/13px), поповер теперь открывается **вниз** с `max-height`/`overflow`, на мобильном `top: auto`.

## Вердикт

**Нужны правки.** Логика React-эффектов и тема в порядке, но геометрия двух изменений ломает интерфейс: поповер «Позиция» на десктопе обрезается (недоступен), а на планшетах/узких ноутбуках (761–1450px) вертикальная карточка игроков «съедает» список ходов до 0px.

Проверка делалась не только чтением: макет собран в изолированной странице с реальными `style.css` / `mobile.css` / `theme.css` / `light.css` / `PositionMenu.css` и измерен в Chromium (Playwright), старые версии CSS взяты из `HEAD` для сравнения.

## 🔴 Блокеры

### 1. Поповер «Позиция» на десктопе уходит под обрезку контейнера

`frontend/src/components/PositionMenu.css:52-63`

```css
/* ...открывается под кнопкой. История ходов теперь по высоте контента,
   поэтому место над кнопкой не гарантировано. */
.position-menu__panel {
  top: calc(100% + 10px);
  bottom: auto;
```

**Что не так.** Комментарий верен только для пустой истории. Как только ходы появились, `.game-history-column > .move-history-panel` получает `flex: 1 1 auto` (`style.css:81-93`), колонка растянута по высоте доски, а `.move-list` с `margin-bottom: auto` (`style.css:2324-2332`) прижимает `.player-info`, навигацию и `.action-buttons` к низу панели. То есть кнопка «Позиция» стоит у нижней границы колонки, и поповер, открывающийся вниз, выходит за неё.

Дальше его режет клиппер: на десктопе `@media (min-width: 1451px)` у `.main-page-scroll` стоит `overflow-y: hidden` (`style.css:344-348`), а у `#root` — `overflow: hidden` (`style.css:216-221`). Ниже кнопки остаётся только `padding-bottom: 12px` у `.main-area` плюс футер (~32px), а панель — 288px.

**Замеры** (Chromium, структура как в `app.jsx:100-104`):

| Вьюпорт | `overflow-y` у `.main-page-scroll` | Поповер | Видно |
|---|---|---|---|
| 1600×900 | hidden | top 843 → bottom 1131 (h 288) | **57px из 288** |
| 1280×800 | auto | top 637 → bottom 925 | 163px, остальное — за фолдом |
| пустая история, 1600×900 | hidden | 303 → 591 | 288/288 ✅ |

В реальном приложении сверху ещё шапка (~80px), т.е. на десктопе будет хуже. Пользователь видит лишь верхнюю кромку меню, кнопки «Загрузить», «Копировать FEN» и «Экспорт» недостижимы (контейнер не скроллится). Дополнительно `PositionMenu.jsx:104` переводит фокус в поле FEN внутри обрезанной области — для клавиатуры это тоже регресс: фокус уезжает в невидимое поле.

**Предложение.** Не полагаться на «снизу всегда есть место»:

- либо вернуть `bottom: calc(100% + 10px)` и `top: auto` для десктопа, оставив открытие вниз только для пустой истории (например, класс-модификатор с панели: `.position-menu--drop-down`);
- либо считать направление в JS (мерить `getBoundingClientRect()` кнопки и `window.innerHeight` перед открытием) или рендерить панель в портал с `position: fixed` на десктопе (на мобильном уже так).

Если пойти по первому пути — комментарий в CSS поправить, он сейчас утверждает неверное.

### 2. На ширинах 761–1450px список ходов сжимается в 0px

`frontend/style.css:2366-2406` (вертикальная `.player-info`), `frontend/src/mobile.css:77-84` (`max-height: 290px` для панели на планшете)

**Что не так.** В диапазоне `@media (max-width: 1450px) and (min-width: 761px)` панель истории ограничена `max-height: 290px`, а `.player-info` на телефонах скрывается только при `max-width: 760px` (`mobile.css:680-682`). Вертикальная карточка занимает 85px вместо прежних 58px (`min-height: 58px` упиралась в горизонтальную раскладку), и эти +27px выжимают единственный сжимаемый элемент — `.move-list`.

**Замеры** (Chromium, те же CSS):

| Ширина | Список ходов, до правки | после правки |
|---|---|---|
| 1200×900 | 18px | **0px** |
| 900×800 | 18px | **0px** |
| 1200×900, `.player-info {display:none}` | — | 72px |

То есть на планшетах в ландшафте и ноутбуках 1366×768 (типовой кейс) история ходов не отображается вообще — ни одной строки. До правки там был «огрызок» в половину строки, т.е. блок был уже тесным, но сейчас он превращается из плохого в неработающий.

**Предложение.** Один из вариантов:

- скрывать `.player-info` не только на `≤760px`, но и в планшетном диапазоне (сейчас она дублирует информацию с доски и там не нужна);
- поднять `max-height` панели в планшетном блоке (`mobile.css:77`) с 290px до ~340-360px;
- либо сделать карточку компактнее на 761–1450px (уменьшить `padding` строк / аватар).

## 🟡 Стоит исправить

### 3. Новый текст ошибки при 401 недостижим, `error` не виден на пустой странице

`frontend/src/components/UserProfilePage.jsx:344-356` и `:368-376`

Сообщение «Сессия истекла. Войдите в аккаунт, чтобы обновить профиль.» практически не может отрисоваться. Любой 401 от `/api/auth/me` обрабатывает интерсептор: либо `refreshSession()` проходит (тогда ошибки в компоненте нет вообще), либо `requireLogin()` (`api.js:176-206`) вызывает `clearAuth()` + `AUTH_EXPIRED_EVENT`, `app.jsx:343-350` делает `setUser(null)`, эффект `[user]` (`UserProfilePage.jsx:305-316`) обнуляет `profile`, и компонент уходит в ранний `return` «Войдите в аккаунт, чтобы открыть профиль…» (`:368-376`), где `error` не выводится вовсе.

Итог: ветка `status === 401` — мёртвый код, а улучшенная формулировка не доходит до пользователя (максимум — один кадр мигания карточки до того, как придёт `AUTH_EXPIRED`).

**Предложение.** Либо убрать специальный текст и оставить общий `detail/message`, либо показывать `error` в пустом состоянии (передать его в `user-profile-empty`), тогда про истёкшую сессию действительно будет сказано.

### 4. Вертикальная карточка игроков игнорирует переворот доски и игру за чёрных

`frontend/src/components/MoveHistory.jsx:80-93`, `frontend/style.css:2374-2382`

Комментарий утверждает «так карточка совпадает с ориентацией доски (свой цвет всегда у нижнего края)», но доску можно перевернуть: `Chessboard.jsx:1459` (`setBoardFlipped(color === "b")` при выборе чёрных) и `Chessboard.jsx:3614` (кнопка «↺ Доска»). При игре за чёрных или после переворота соперник оказывается снизу, а карточка продолжает рисовать пользователя внизу — прямое расхождение с доской, причём заявленное как фича.

**Предложение.** Пробросить в `MoveHistory` `flipped` (или `playerColor`) из `app.jsx:105-118` и менять порядок строк, либо убрать из комментария обещание синхронизации с доской.

### 5. `setError("")` при любом обновлении `user` стирает реальную ошибку загрузки

`frontend/src/components/UserProfilePage.jsx:305-316`

Эффект срабатывает на любое изменение объекта `user`, а родитель обновляет его не только при логине: `app.jsx:322` (серия пазлов) и `:330` (тост GigaCoin) делают `setUser({ ...current, ... })`. Если `/me` упал по сети и карточка показывает «Не удалось обновить данные профиля», достаточно получить GigaCoin в другой вкладке — сообщение молча исчезнет.

**Предложение.** Сбрасывать ошибку по конкретному признаку (смена `user?.id`, успешный ответ `/me`) или очищать её в `handleNicknameChanged`/после успешного fetch, а не на каждом изменении ссылки `user`.

### 7. Объявления-пустышки в карточке игроков

- `MoveHistory.jsx:97` — класс `player-info__row--self` нигде не стилизован: в CSS есть только `--opponent` (`style.css:2404-2406`). Либо добавить правило, либо убрать класс.

### 8. `vh` вместо `dvh` у `max-height` поповера

`PositionMenu.css:62` (`calc(100vh - 120px)`), `:205` (`calc(100vh - 140px)`)

На мобильном `vh` не учитывает схлопывание адресной строки — панель может оказаться выше видимой области. Для фиксированного листа внизу экрана уместнее `100dvh`.

## Проверено, претензий нет

- **Золотая карточка GigaCoin.** Причина правки подтверждена: базовый `.user-profile-stat` (`background: #f7faf7`) стоит в файле **после** старого `.user-profile-stat--coins` с той же специфичностью (0,1,0) и перекрывал градиент. С новым селектором (0,3,0) в светлой теме считаются `linear-gradient(135deg, #fffaf0, #f6f0df)` и `#806127`, в тёмной — по-прежнему тёмный золотой градиент из `UserProfilePage.css:474` (0,4,0, перекрывает и `theme.css:1446`). Ховер (`UserProfilePage.css:493`, 0,3,0, идёт позже) продолжает работать.
- **Встраивание уровня в «Прогресс».** `RatingBandProgress` имеет свойство `width: 100%`, фон прозрачный, разделитель только `border-bottom` (в тёмной теме — золотой, `UserProfilePage.css:481`). `.progress-widget` внутри секции действительно «плоский» в обеих темах (`padding: 0`, без рамки и тени); тёмное переопределение `:486` не избыточно — без него правило `:435` (0,3,0) вернуло бы панель. `RatingBandProgress` при отсутствии `current_band` возвращает `null`, поэтому «висячего» разделителя не бывает.
- **React-эффекты профиля.** `profile` не теряется при обычном обновлении `user` (`onUserChange` — это стабильный `setUser` из `app.jsx:467`, зацикливания нет); гонка отменяется флагом `cancelled`; отсутствие токена больше не приводит к ложному «Требуется пройти анкету»; при выходе кэш-профиль скрывается, потому что `clearAuth()` и `setUser(null)` идут парой. Мигание «Войдите в аккаунт» при загрузке (`loading` инициализируется как `Boolean(user)`) предсуществующее и правкой не ухудшено.
- **Мобильное меню «Позиция».** `top: auto` корректно перебивает `top: calc(100% + 10px)`: при 390×844 панель `position: fixed`, `bottom: 96px`, видна целиком (288/288), бэкдроп на месте. Кнопка на мобильном — 104×28 по центру.
- **Размер кнопки на десктопе.** `width: auto; min-width: 116px` даёт фактически 116×30 по центру колонки (кнопка shrink-to-fit + `margin: 0 auto`), как и задумано.
- **Пустая история.** `move-history-panel--empty` с `flex: 0 0 auto` (0,2,0, позже базового правила) работает: панель по контенту, поповер при пустой истории виден полностью; на `≤760px` правило не конфликтует с `max-height: 290px`.
- **Темы карточки игроков.** Вертикальный градиент в `style.css:2374-2382` (соперник сверху — бумага, игрок снизу — зелёный) согласован с новым DOM; тёмный вариант `theme.css:204-214` перевёрнут в ту же сторону. Раскладка проверена скриншотом: VS-жетон стоит на стыке и не перекрывает ни имя, ни рейтинг.
- **Доступность меню.** `aria-haspopup="dialog"`, `aria-expanded`, `role="dialog"`, закрытие по Escape и клику вне, автофокус в поле FEN — на месте (кроме последствий блокера №1).

## Что осталось непроверенным

- Реальный бэкенд не поднимался: 401/refresh-сценарии и поведение `AUTH_EXPIRED_EVENT` разбирались по коду `api.js`/`app.jsx`, не в живом прогоне.
- Скриншот-проверка ограничена Chromium; Firefox/Safari (в частности shrink-to-fit у `button` с `display: flex` и `overflow: hidden` на `#root`) не прогонялись.
- `e2e/pages.spec.js` эти экраны не покрывает, поэтому регрессии из блокеров №1–2 автотестами не ловятся — при исправлении стоит добавить хотя бы проверку видимости панели «Позиция» после хода на десктопном вьюпорте.
- Визуальная оценка «плоского» `ProgressWidget` в состояниях `loading`/`error` (текст без внутреннего паддинга) — на реальных данных не смотрел.
