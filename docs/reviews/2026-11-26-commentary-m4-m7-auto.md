## Находки

- 🔴 `ml/benchmark/gigabench/commentary.py:1020` — `sum(r.get("critical_error") for r in rows)` падает на пустом или обрезанном ответе: ранний возврат `score_response` (753–759) не содержит `critical_error`, поэтому слагаемое равно `None`. Даже один такой ответ делает `score_run` неработоспособным вместо обещанных нулей. Предложение: суммировать `M6` либо задать `critical_error=False` в базовом результате. Добавить end-to-end тесты `score_run` для пустого, обрезанного и смешанного набора: существующий тест проверяет лишь `score_response`.

- 🔴 `ml/benchmark/gigabench/commentary.py:485–495` — отрицания распознаются только для узких форм «не шах», «без шаха», «не ошибка». Для стартового `e2e4` корректное «Пешка идёт с e2 на e4 и не даёт шаха» превращается в положительный claim шаха и получает M6=1. Аналогично «Это не мат» получает положительный claim мата; «Это не грубая ошибка» — противоположный вердикт. Отрицания взятия/рокировки/превращения также не учитываются (456–463). Предложение: учитывать отрицание в пределах соответствующего предиката, хранить ожидаемую полярность; неоднозначное утверждение пропускать, а не объявлять критической ошибкой. Добавить пары положительных и отрицательных формулировок для каждого вида claim.

- 🔴 `ml/benchmark/gigabench/commentary.py:448–451,526` — теряется суффикс превращения UCI: из `a7a8q` сохраняются лишь клетки, затем рекомендация проверяется как `a7a8`, который нелегален. В позиции `7k/P7/8/8/8/8/8/7K w - - 0 1` корректное «Лучше сыграть a7a8q» получает M6=1. Предложение: сохранять полный UCI/promotion в claim и использовать его для проверки легальности; словесную рекомендацию без указания фигуры превращения считать неоднозначной. Добавить тесты легального превращения и underpromotion.

- 🔴 `ml/benchmark/gigabench/commentary.py:395–405` — отсечение будущего/прошлого контекста удаляет весь остаток предложения, включая самостоятельные проверяемые утверждения о сыгранном ходе. Например, для стартового `e2e4` из «Белая пешка идёт с e2 на e4, угрожает занять центр, а сыгранный ход объявляет шах» останется только правильный переход. Ложный шах не попадёт в M6; с отдельным «Это точный ход» ответ удовлетворяет всем порогам приёмки. Фраза «Был сыгран ход с d2 на d4» вообще теряется из-за начального «был». Предложение: отделять утверждения по клаузам и восстанавливать текущий контекст при явном указании сыгранного хода, а не отбрасывать весь суффикс; добавить обе регрессии.

- 🟡 `ml/benchmark/gigabench/commentary.py:960–967` — проверка версии критериев и хэшей выполняется только при явном `--suite`. Обычный `score --run` читает подготовленные cases без проверки собственного manifest и публикует текущую версию критериев даже при изменённой рубрике/старой версии. Предложение: одинаково валидировать manifest выбранного `suite_path` в обоих режимах; добавить тест изменения cases после prepare и несовместимой версии.

## Что хорошо

- M4 делится только на confirmed/incorrect; случай отсутствия проверяемых claims защищён от деления на ноль.
- При проверке вердикта используется `rubric.allowed_facts.verdict`; при построении рубрики target имеет приоритет над engine.
- Queries собираются явным списком полей без reference answer; cases помечены private.
- Unknown IDs отклоняются, missing IDs требуют явного allow-partial; в summary указана полнота.
- Отчёт прямо отделяет автоэвристику от педагогической экспертизы, HTML-поля экранируются.
- Тесты содержат полезные негативные примеры и проверки порогов; однако успешное прохождение эталонов не заменяет регрессии для отрицаний, превращений и смешанного временного контекста.
